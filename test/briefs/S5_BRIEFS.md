## E26 `s5-motion-prompt` — 움직임은 글로 어떻게 쓸까 · 모션 프롬프트의 여섯 축

핵심 주장: 정지 이미지 프롬프트의 네 축(피사체·카메라·조명·분위기)에 영상은 **움직임 축**이 더 붙어요. 영상 모델은 프레임을 시간 축으로 묶어 학습해서(시공간 패치, 시간 축 어텐션) "무엇이 어떻게 움직이는지"가 글에 없으면 가장 흔한 움직임(살짝 흔들림, 카메라 정지)을 골라요.

여섯 축(장면 4에서 카드로): ① 주체의 동작(걷는다, 돌아본다) ② 카메라 무빙(dolly in, pan, orbit, tilt) ③ 속도·리듬(천천히, 일정하게, ease) ④ 시작 상태 → 끝 상태 ⑤ 길이·루프 여부 ⑥ 고정할 것(배경은 그대로, 얼굴 유지).

장면 초안
1. 사례: "쿼카가 교실에 서 있다"로 5초 영상 → 거의 안 움직이거나 카메라만 흔들림. "뭘 어떻게 움직이라는 말이 없었다"
2. 원리: 영상 모델은 프레임 묶음을 시공간 조각으로 자르고, 조각들 사이의 관계(시간 축)를 배워요. 텍스트에 움직임이 없으면 학습 데이터에서 가장 흔한 움직임을 골라요. 도식: 프레임 3장 → 시공간 조각 → 시간 축 화살표.
3. 연구: 텍스트-영상 확산 모델 연구(Make-A-Video 2022: 이미지-텍스트 쌍 + 텍스트 없는 영상으로 움직임 학습 / Stable Video Diffusion 2023 / OpenAI 2024 기술 보고서: 시공간 패치). 자막은 "2022년 연구", "2024년 보고서" 식으로.
4. 여섯 축 카드 + 예시 프롬프트 전후: "쿼카가 교실에 서 있다" → "쿼카가 교실 앞에서 칠판을 향해 천천히 걸어가고, 카메라는 낮은 각도에서 뒤따라가며(dolly in), 5초, 배경은 고정, 마지막에 뒤돌아 웃는다"
5. 정리: 움직임 한 문장 없이는 정지 사진과 같다. 여섯 축을 채우고, 안 되는 건 도구 탓 아니라 문장 탓일 때가 많다. 도구마다 지원하는 카메라 용어가 달라요.

만져 보기 "모션 프롬프트 조립기": 여섯 축 각각 select(2~3 선택지) → 조립된 프롬프트 문장을 실시간 표시 + 오른쪽에 간단한 SVG 미리보기(쿼카 스티커 img가 선택에 따라 좌→우 이동/확대/회전을 CSS transition으로; 카메라 무빙은 프레임 확대, 속도는 duration). primary 버튼 "예시로 채우기"를 누르면 여섯 축이 예시값으로 바뀌고 문장이 생김.

teacherLines: "영상 AI에게는 <b>무엇이 어떻게 움직이는지</b>를 꼭 말해 줘요. 안 말하면 가만히 있거나 카메라만 흔들려요." / "사진 프롬프트에 <b>움직임 한 문장</b>을 더하면 영상 프롬프트가 돼요."
tip: 학급 영상은 "주체 동작 + 카메라 + 길이" 세 가지만 채워도 훨씬 나아져요. 카메라 용어는 영어 병기(dolly in, pan). extra: 안 움직이는 게 목표면 "카메라 고정, 배경 고정"이라고 써야 해요.
myth: "이미지 프롬프트를 그대로 넣으면 영상도 잘 나온다" → 이미지 프롬프트에는 시간이 없어요. 움직임·카메라·길이를 더해야 해요.
sources

- Stable Video Diffusion: Scaling Latent Video Diffusion Models to Large Datasets (arXiv 2023) https://arxiv.org/abs/2311.15127

- Imagen Video: High Definition Video Generation with Diffusion Models (arXiv 2022) https://arxiv.org/abs/2210.02303

## E27 `s5-upscale` — 업스케일은 없는 픽셀을 어디서 가져올까 · 초해상도

핵심 주장: 작은 그림을 키우면 없던 픽셀이 필요해요. 옛 방식(보간)은 주변 픽셀 평균으로 채워서 흐릿하고, 생성형 업스케일은 "이런 무늬는 보통 이렇게 생겼다"는 학습된 패턴으로 **그럴듯하게 그려 넣어요**. 그래서 선명하지만 없던 세부가 생기고, 글자·얼굴·로고처럼 정답이 있는 곳에서 틀릴 수 있어요.

장면 초안
1. 사례: 학급 사진을 4배 키웠더니 선명해졌는데 이름표 글자가 다른 글자로 바뀌었다.
2. 원리 1: 보간. 2×2 픽셀을 4×4로 늘리면 새 칸은 이웃의 평균 → 흐림. 격자 도식(P.h div 격자).
3. 원리 2: 생성형 초해상도. 흐린 입력을 조건으로 잡음에서 세부를 그려 넣음(SR3 2021: 확산 모델로 초해상도 / SRGAN 2017: 적대 학습으로 "진짜 같은" 질감 / Real-ESRGAN 2021: 실제 열화 흉내). 자막은 "2017년 연구" 식.
4. 어디서 틀리나: 정답이 있는 것(글자·숫자·얼굴·로고) vs 정답이 없는 것(풀·머리결·구름). 전자는 확인 필수.
5. 정리: 업스케일은 복원이 아니라 추정. 원본 해상도로 다시 생성할 수 있으면 그게 낫고, 키운 뒤엔 글자·얼굴 확대 확인.

만져 보기 "보간 vs 생성 업스케일 비교": 8×8 격자 픽셀 아트(쿼카 실루엣 정도, 코드로 색 배열)를 왼쪽은 보간(각 셀을 평균으로 부드럽게), 오른쪽은 "생성"(결정적 규칙으로 가장자리에 그럴듯한 세부·질감을 추가하되 시드 기반으로 몇 군데는 틀린 세부 삽입, 틀린 곳은 토글로 표시). range로 배율 1~4, primary 버튼 "틀린 세부 표시"로 오른쪽에 빨간 테두리 표시. 캔버스는 width:100%;height:auto.

teacherLines: "업스케일은 <b>없던 픽셀을 그럴듯하게 그려 넣는</b> 거예요. 복원이 아니라 추정이에요." / "키운 사진의 <b>글자와 얼굴</b>은 꼭 확대해서 확인해요."
tip: 사진 키우기 전에 원본이 더 큰 파일이 있는지 먼저 찾기. 키운 뒤 글자·얼굴·로고는 원본과 대조. extra: 인쇄용은 배율을 낮게 두 번 나눠 키우는 편이 덜 망가질 때가 있어요(도구마다 달라요).
myth: "업스케일하면 원래 화질이 돌아온다" → 사라진 정보는 돌아오지 않아요. 학습된 패턴으로 채운 추정이에요.
sources
- Photo-Realistic Single Image Super-Resolution Using a Generative Adversarial Network (SRGAN, arXiv 2016) https://arxiv.org/abs/1609.04802
- Image Super-Resolution via Iterative Refinement (SR3, arXiv 2021) https://arxiv.org/abs/2104.07636
- Real-ESRGAN: Training Real-World Blind Super-Resolution with Pure Synthetic Data (arXiv 2021) https://arxiv.org/abs/2107.10833

## E28 `s5-guidance` — 네거티브 프롬프트는 정말 빼 줄까 · 안내 강도(CFG)

핵심 주장: 확산 모델은 매 단계 두 번 예측해요. "프롬프트 있음"과 "프롬프트 없음(또는 네거티브)". 그 차이를 **안내 강도(CFG scale)**만큼 키워서 프롬프트 방향으로 밀어요. 네거티브 프롬프트는 "없음" 자리에 들어가서 반대 방향으로 밀어내는 것. 강도가 너무 높으면 색이 타고 과포화, 너무 낮으면 프롬프트를 안 따름. 네거티브는 초반 단계에서 주로 효과가 나고 만능이 아니에요(2024년 분석 연구).

장면 초안
1. 사례: "손가락 여섯 개 빼 줘"를 네거티브에 넣었는데 여전히 여섯 개. 반대로 안내 강도를 15로 올렸더니 색이 타 버렸다.
2. 원리: 두 예측(조건/무조건)과 그 차이 벡터. 도식: 점 두 개와 화살표, 강도 슬라이더 개념. "2022년 연구가 제안한 분류기 없는 안내"
3. 네거티브: "무조건" 자리에 네거티브를 넣으면 그 방향에서 멀어짐. 하지만 개념이 모델 안에 뚜렷해야 하고, 초반 단계에서 효과가 크며, 늦게 넣으면 거의 안 먹음(2024년 분석).
4. 강도 스펙트럼: 낮음(프롬프트 무시, 다양) ↔ 적당(보통 5~9 근처, 도구마다 다름) ↔ 높음(과포화·타 버림·경직). 막대 카드 3개.
5. 정리: 네거티브는 마법이 아니라 방향 하나 더. 손가락 같은 건 네거티브보다 레퍼런스·포즈 조건(다음 편)이 낫다. 강도는 기본값 근처에서 조금씩.

만져 보기 "안내 강도 다이얼": 캔버스에 색 점(결정적)으로 "프롬프트 방향" 과녁과 샘플 점들. range 0~20으로 안내 강도 → 점들이 과녁으로 모이되 15 이상이면 색이 과포화(채도 UI 변화)·점들이 한 덩어리로 뭉침. primary 버튼 "네거티브 켜기"로 반대 방향 원(네거티브 개념)에서 점들이 밀려남. 아래에 상태 문장("강도 7: 프롬프트를 따르면서 다양해요").

teacherLines: "AI 그림은 <b>프롬프트 방향으로 얼마나 세게 미느냐</b>를 정하는 손잡이가 있어요. 너무 세면 색이 타요." / "네거티브 프롬프트는 <b>반대로 미는 힘</b>이지, 지우개가 아니에요."
tip: 강도는 도구 기본값에서 시작해 ±2씩. 네거티브에는 뚜렷한 개념(흐림, 워터마크, 글자)만. 손가락·개수는 네거티브로 잘 안 잡혀요. extra: 도구가 강도 슬라이더를 안 보여 주면 이미 적당히 잡혀 있는 거예요.
myth: "네거티브에 쓰면 무조건 사라진다" → 반대 방향으로 밀 뿐이고, 모델이 그 개념을 뚜렷이 알아야 하고, 초반 단계에서만 주로 효과가 있어요.
sources
- Classifier-Free Diffusion Guidance (arXiv 2022) https://arxiv.org/abs/2207.12598
- Understanding the Impact of Negative Prompts: When and How Do They Take Effect? (arXiv 2024) https://arxiv.org/abs/2406.02965

## E29 `s5-controlnet` — 포즈를 지정하면 왜 말을 들을까 · 컨트롤넷과 조건부 생성

핵심 주장: 글은 "무엇"은 잘 전하지만 "어디에 어떤 자세로"는 약해요. 컨트롤넷(2023)은 스케치·포즈 뼈대·깊이·윤곽 같은 **공간 조건 그림**을 생성 과정에 한 겹 더 넣는 방식. 원래 모델은 얼려 두고 복사본 가지를 붙여 조건을 배우니 기존 그림 실력은 유지되고 배치만 따름. 레퍼런스 이미지(E07)가 "누구"를 붙잡는다면 컨트롤넷은 "어디에 어떻게"를 붙잡아요.

장면 초안
1. 사례: "왼손을 들고 오른쪽을 보는 쿼카"를 글로 열 번 써도 매번 다르게. 포즈 뼈대 그림 한 장 넣으니 한 번에.
2. 원리: 조건 그림(뼈대·윤곽·깊이)이 생성 단계마다 함께 들어감. 도식: 프롬프트 + 조건 그림 → 모델 → 결과. "2023년 연구"
3. 왜 실력이 안 망가지나: 원본 가중치 고정 + 복사 가지 + 0으로 시작하는 연결(zero conv). 비유: 숙련된 화가 옆에 자세 코치를 붙인 것. T2I-Adapter(2023)도 비슷한 가벼운 방식.
4. 조건 종류 카드: 포즈 뼈대(OpenPose 2018 같은 자세 추정으로 뽑음), 윤곽선(캐니), 깊이, 낙서. 각각 무엇을 고정하는지.
5. 정리: 누구=레퍼런스 이미지, 어디에 어떻게=조건 그림, 무엇=프롬프트. 셋을 나눠 생각하면 손가락 개수·자세 문제의 절반은 풀려요. 도구마다 이름이 달라요(구조 참조, 포즈 참조, 스케치 모드).

만져 보기 "조건 켜고 끄기": 캔버스에 뼈대(선분 5~6개, 결정적 좌표)를 드래그 없이 select로 포즈 3종 선택 → primary 버튼 "조건 켜기"를 누르면 오른쪽 결과 칸의 쿼카 스티커가 그 뼈대 각도에 맞춰 회전·팔 위치(간단한 CSS transform 조합) → 끄면 시드 기반 무작위 포즈. "다른 시드" 버튼.

teacherLines: "글은 '무엇'을, 그림 조건은 <b>'어디에 어떤 자세로'</b>를 전해요. 자세는 그림으로 주는 게 빨라요." / "누구는 레퍼런스 사진, 자세는 뼈대 그림, 나머지는 글. <b>세 가지를 나눠서</b> 줘요."
tip: 학급 캐릭터 포스터는 포즈 뼈대 1장을 미리 만들어 두고 재사용. 조건 강도 슬라이더가 있으면 0.6~0.8 근처부터. extra: 조건 그림과 프롬프트가 싸우면(뼈대는 앉았는데 글은 달린다) 이상하게 나와요. 둘을 맞추세요.
myth: "포즈 지정은 프롬프트를 자세히 쓰면 된다" → 글은 공간 배치를 정확히 못 전해요. 뼈대·스케치 같은 조건 그림이 필요해요.

## E30 `s5-long-video` — 긴 영상은 왜 뒤로 갈수록 무너질까 · 시간 일관성

핵심 주장: 영상 모델은 한 번에 다룰 수 있는 프레임 수(시간 창)가 정해져 있어요. 긴 영상은 앞 조각의 끝을 다음 조각의 시작으로 이어 붙이거나(자기회귀 확장), 앞 조각을 조건으로 다음을 만들어요. 그러면 E25의 편집 사슬처럼 작은 오차가 누적되어 색이 바래고 얼굴이 바뀌고 물체가 사라져요(드리프트). 해소: 짧게 여러 번 + 키프레임(정면 레퍼런스)을 각 조각에 다시 넣기 + 장면 전환은 편집에서.

장면 초안
1. 사례: 30초 영상 한 번에 만들었더니 10초 뒤부터 쿼카 스웨터 색이 바래고 20초엔 딴 쿼카.
2. 원리: 시간 창(한 번에 N프레임) 도식 + 조각 이어 붙이기 → 조각마다 앞 조각을 참고 → 오차 누적(드리프트). E25 사슬과 같은 원리.
3. 연구: 한 번에 전체 길이를 다루려는 시도(2024년 시공간 전체를 한 번에 만드는 연구 Lumiere), 조각을 이어 가며 장기 기억을 넣는 시도(StreamingT2V 2024), 잡음 스케줄을 바꿔 이어 붙이는 시도(FreeNoise 2023). 자막은 "2024년 연구" 식.
4. 해소법 카드: ① 5~10초 조각으로 나누기 ② 조각마다 정면 레퍼런스 다시 넣기 ③ 마지막 프레임을 다음 조각 시작 이미지로 쓰되 2~3번 넘기면 레퍼런스로 리셋 ④ 장면 전환은 편집 프로그램에서 붙이기
5. 정리: 긴 영상은 "긴 한 방"이 아니라 "짧은 여러 방 + 같은 레퍼런스". 도구마다 최대 길이·확장 방식이 달라요.

만져 보기 "드리프트 누적 시뮬레이터": 타임라인 0~30초 range. 쿼카 스티커의 색(hue-rotate)·크기·기울기가 시간에 따라 결정적으로 누적 드리프트(사슬). primary 버튼 "레퍼런스 리셋 켜기"를 누르면 10초마다 원본으로 리셋되어 드리프트가 작게 유지. 두 개를 나란히(사슬 vs 리셋) 보여 주고 "일치도 %" 표시.

teacherLines: "영상 AI는 <b>짧은 조각</b>을 이어 붙여 긴 영상을 만들어요. 그래서 뒤로 갈수록 조금씩 달라져요." / "긴 영상은 <b>짧게 여러 번</b> 만들고, 조각마다 같은 레퍼런스를 넣어요."
tip: 학급 영상은 5~10초 조각 × 여러 개 + 편집 프로그램에서 이어 붙이기. 조각마다 정면 레퍼런스. extra: "이어서 생성" 기능은 두세 번까지만, 그다음엔 레퍼런스로 리셋.
myth: "최대 길이까지 한 번에 뽑는 게 제일 자연스럽다" → 뒤로 갈수록 드리프트가 쌓여요. 짧은 조각 + 같은 레퍼런스가 더 안정적이에요.
