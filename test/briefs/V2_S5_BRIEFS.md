## 33 `v5-model-collapse` — AI가 AI가 쓴 글만 먹고 자라면 어떻게 될까

- 부제: 모델 붕괴와 합성 데이터
- summary: 인터넷에 AI가 쓴 글이 늘면 다음 AI는 그 글로 배우게 돼요. AI 생성물로만 거듭 학습하면 드문 것부터 잊고 한 가지 말만 반복하는 "모델 붕괴"의 원리와, 사람이 쓴 원본 데이터를 지키면 피할 수 있다는 연구를 정리해요.
- keywords: 모델 붕괴, 합성 데이터, 재귀 학습, 분포의 꼬리, 다양성, 데이터 출처, MAD, 실제 데이터 누적

### 확인된 사실 목록
1. 2024년 네이처 논문(Shumailov 외, "AI models collapse when trained on recursively generated data", Nature 631권): 앞 세대 모델이 만든 데이터로 다음 모델을 학습시키는 일이 반복되면 모델이 원래 데이터 분포를 잊어 가는 퇴행 과정을 "모델 붕괴"라고 불러요. — https://www.nature.com/articles/s41586-024-07566-y (게재 2024-07-24)
2. 같은 논문: **초기 붕괴**에서는 확률이 낮은 사건(분포의 꼬리)이 먼저 사라지고, **후기 붕괴**에서는 분산이 크게 줄어 원래 데이터와 거의 닮지 않은 좁은 분포로 수렴해요. — 같은 URL
3. 같은 논문: 언어 모델(OPT-125m), 변분 오토인코더(VAE), 가우스 혼합 모델(GMM)에서 모두 확인했어요. 오차의 출처는 세 가지 — 표본 수가 유한해서 생기는 통계적 근사 오차, 신경망 표현력의 한계(함수 표현력 오차), 학습 방법의 한계(함수 근사 오차). — 같은 URL
4. 같은 논문의 언어 모델 실험(wikitext2): 원본 데이터를 하나도 남기지 않은 설정은 성능이 크게 나빠졌고, **세대마다 원본 데이터 10%를 남긴 설정은 성능 저하가 작았어요**. 9세대 출력 예시는 건축 이야기로 시작한 글이 꼬리 색깔만 바꾼 산토끼 이름을 줄줄이 반복하는 문장으로 무너져 있어요. — 같은 URL
5. 같은 논문 결론: 원래 데이터 원천에 대한 접근을 유지해야 하고, LLM 생성 콘텐츠가 늘수록 사람이 실제로 상호작용한 데이터의 가치가 커지며, AI 생성물과 사람 작성물을 구별하는 것(데이터 출처 관리)이 중요해요. — 같은 URL
6. 같은 연구진의 앞선 공개본(2023): "모델 생성 콘텐츠로 학습하면 원래 분포의 꼬리가 사라지는 되돌릴 수 없는 결함이 생긴다". — https://arxiv.org/abs/2305.17493 (arXiv v1 2023-05-27, 최종 2024-04-14)
7. 2024년 연구(Gerstgrasser 외): 실제 데이터를 세대마다 합성 데이터로 **갈아 끼우면** 붕괴로 가지만, 원래 실제 데이터 옆에 합성 데이터를 **쌓아 가면(누적)** 붕괴를 피했어요. 언어 모델·확산 모델·VAE에서 같은 결과. — https://arxiv.org/abs/2404.01413 (arXiv 2024-04-01, 수정 2024-04-29)
8. 2023년 연구(Alemohammad 외, "Self-Consuming Generative Models Go MAD"): 자기 소비 고리에서 세대마다 새 실제 데이터가 충분하지 않으면 품질(정밀도)이나 다양성(재현율)이 점점 떨어져요. 이를 "모델 자가포식 장애(MAD)"라고 불러요. — https://arxiv.org/abs/2307.01850 (arXiv 2023-07-04)
9. 합성 데이터가 쓸모 있는 사례(2023, "Textbooks Are All You Need"): 1.3B 파라미터 코드 모델 phi-1을 골라 낸 웹 데이터 60억 토큰 + GPT-3.5로 만든 합성 교과서·연습문제 10억 토큰으로 학습해 HumanEval 50.6%를 냈어요. 핵심은 "데이터 품질과 큐레이션". — https://arxiv.org/abs/2306.11644 (arXiv 2023-06-20)
- 확인 불가: 네이처 논문 언어 모델 실험의 정확한 퍼플렉시티 수치(요약 과정에서 숫자가 섞여 확인 불가). 자막에 수치로 쓰지 말고 "크게 나빠졌다 / 조금만 나빠졌다"로.

### 장면 5개 초안
1. 복사본의 복사본 — 쿼카(think)가 "건축 이야기"로 시작한 글이 세대를 거치며 바뀌는 카드 3장(1세대 정상 → 5세대 반복 늘어남 → 9세대 "꼬리 색만 다른 산토끼" 나열). 자막: "AI가 쓴 글로 다음 AI를 가르치고, 또 그 AI가 쓴 글로 다음 AI를 가르쳤더니 9세대에서 이렇게 됐어요. 2024년 네이처에 실린 실험이에요."
2. 드문 것부터 사라져요 — 종 모양 막대그래프(P.h 막대 12개). 세대마다 "표본 뽑기 → 다시 학습" 화살표, 양 끝 막대가 하나씩 0이 됨. 자막: "AI는 배운 분포에서 표본을 뽑아 글을 써요. 표본은 유한해서 드문 것은 안 뽑힐 때가 있고, 다음 세대는 그걸 아예 모르게 돼요." 용어: 분포의 꼬리 = 드물게 나오는 표현·사례.
3. 초기 붕괴, 후기 붕괴 — 카드 2장: "초기: 꼬리가 사라져요" / "후기: 폭이 좁아져 한 점으로 모여요". 칩: "언어 모델·VAE·GMM 모두 확인". 자막에 오차 세 가지 중 하나만(표본이 유한해서 생기는 오차).
4. 원본을 지키면 버텨요 — 막대 두 줄 비교: "원본 0% 남김: 크게 나빠짐" vs "원본 10% 남김: 조금만 나빠짐"(사실 4). 아래 칩 2개: "갈아 끼우면 붕괴, 쌓아 가면 피함(2024년 연구)" / "잘 골라 만든 합성 데이터는 도움이 되기도 해요(2023년 연구)". 자막: "합성 데이터가 문제가 아니라, 실제 데이터를 버리고 합성 데이터로 갈아 끼우는 게 문제예요."
5. 교실에서는 — 쿼카(wave). 박스 3개: "사람이 쓴 원본 따로 보관" / "AI 생성물에는 표시" / "드문 이야기(우리 동네, 우리 반)를 기록". 자막: "AI 생성물이 늘수록 사람이 직접 쓴 글의 가치가 커져요. 표시는 다음 AI를 위한 출처 관리이기도 해요."

### 만져 보기
- title: 세대 복사기
- 화면: 단어 카드 12종(쿼카·코알라·웜뱃·오리너구리·캥거루·에뮤·딩고·주머니쥐·포섬·바늘두더지·태즈메이니아데빌·쿠올)의 처음 빈도 [30,20,14,10,8,6,4,3,2,1,1,1](합 100)을 막대로 표시.

### tip
- body: 학급 자료실에 AI로 만든 자료를 넣을 때는 파일 이름이나 첫 줄에 "AI 생성"을 표시하고, 사람이 쓴 원본은 따로 폴더를 두세요. AI 초안을 고쳐 쓰는 활동이라면 원본(학생 문장)과 AI 문장을 색으로 구분해 남기게 하세요.

### myth
- myth: 인터넷에 AI가 쓴 글이 많아질수록 AI는 더 많이 배워서 똑똑해진다.
- fact: AI 생성물로 거듭 학습하면 드문 표현부터 사라지는 모델 붕괴가 일어나요. 사람이 쓴 실제 데이터를 버리지 않고 함께 쌓아야 버텨요.

## 34 `v5-open-weight` — 공개된 모델과 닫힌 모델, 무엇이 다를까

- 부제: 오픈 웨이트, 라이선스, 전문가 혼합(MoE)

Gemma 4 공식 문서: Gemma 4는 Apache 2.0 라이선스이고, E2B·E4B·12B·**26B A4B(MoE, 활성 4B)**·31B(조밀) 네 가지 구조. — https://ai.google.dev/gemma/docs/core (페이지 갱신 2026-07-08). 공식 모델 카드: gemma-4-26b-a4b-it 라이선스 "Apache 2.0", 전체 25.2B·**활성 3.8B**, 전문가 128개 중 8개 + 공유 전문가 1개, 문맥 256K. — https://huggingface.co/google/gemma-4-26b-a4b-it
   - 반영: **같은 모델 가족도 버전에 따라 라이선스가 바뀐 실제 사례**(Gemma 3까지 커스텀 약관 → Gemma 4는 Apache 2.0).
7. 2024년 Mixtral 논문: 층마다 피드포워드 블록(전문가) 8개, **토큰마다 라우터가 2개를 골라** 결과를 합쳐요. 전체 47B 파라미터지만 추론 때는 13B만 활성. 가중치는 Apache 2.0으로 공개. — https://arxiv.org/abs/2401.04088 (arXiv 2024-01-08)
8. 오픈 소스 이니셔티브(OSI)의 "Open Source AI Definition 1.0": 사용·연구·수정·공유 네 가지 자유를 요구하고, 이를 위해 **데이터 정보**(숙련자가 거의 같은 시스템을 만들 수 있을 만큼 상세한 학습 데이터 정보), **코드**(학습·실행 전체), **파라미터(가중치)** 셋을 모두 공개하라고 정의해요. — https://opensource.org/ai/open-source-ai-definition (발표일은 페이지에서 확인 불가)
   - 반영: "오픈 웨이트(가중치 공개)"와 "오픈 소스 AI(데이터 정보·코드·가중치 모두)"는 다른 말.
- 확인 불가: gpt-oss 공개일, OSI 정의 발표일, MoE가 전체 가중치를 메모리에 올려야 한다는 공식 수치(메커니즘 설명으로만 쓰고 수치 금지).

### 장면 5개 초안
1. 내려받아도 되나요? — 쿼카(think). 연구회 문자 박스 "무료로 내려받는 모델, 학교 서버에 깔아도 돼요?". 모델 카드 모형 3장의 라이선스 칸만 강조: "apache-2.0" / "mit" / "llama3.1(커스텀)". 자막: "모델 카드 맨 위에 라이선스 칸이 있어요. 여기 적힌 세 갈래가 쓸 수 있는 조건을 정해요."
2. 오픈 웨이트란 — 도식: 닫힌 모델(질문 → 회사 서버 → 답, 가중치는 안 보임) vs 오픈 웨이트(가중치 파일 다운로드 → 내 컴퓨터에서 실행). 용어: 가중치 = 학습으로 정해진 수십억 개의 숫자. 칩: "가중치 공개 ≠ 학습 데이터 공개". 자막: "오픈 소스 정의를 만드는 단체는 오픈 소스 AI라면 데이터 정보·코드·가중치 셋을 다 공개하라고 해요." (OSI 정의 발표 연도는 확인 불가라 자막에 연도 쓰지 않음)
3. 라이선스 세 갈래 — 카드 3장. Apache-2.0: 사용·수정·배포 자유, 특허 조항(gpt-oss, Qwen3, Gemma 4) / MIT: 짧고 자유, 증류까지 허용 명시(DeepSeek-R1) / 커스텀: 이용자 7억 명 조건, "Built with Llama" 표시, 이름 앞 Llama, 금지 용도 정책(Llama 3.1, Gemma 3까지). 자막: "같은 Gemma도 3까지는 자체 약관, 4부터는 Apache 2.0이에요. 버전마다 라이선스 칸을 다시 봐요."
4. 전문가 혼합(MoE) — 격자 도식: 전문가 칸 8개 중 라우터가 토큰마다 2칸 점등(Mixtral). 숫자 카드: "전체 47B / 일하는 13B", "30.5B / 3.3B(전문가 128 중 8)". 자막: "MoE는 층마다 전문가 여러 개를 두고, 라우터가 토큰마다 몇 명만 골라 계산해요. 그래서 크기에 비해 빨라요." 이어서: "모델 이름의 A3B는 활성 파라미터가 약 3B라는 표시예요."
5. 학교에서의 의미 — 쿼카(point). 저울 도식: 왼쪽 "장점: 학교 기기에서 돌리면 글이 밖으로 안 나가요, 버전 고정" / 오른쪽 "책임: 라이선스·금지 용도 지키기, 안전 필터와 업데이트는 학교 몫". gpt-oss-20b 예: "16GB 메모리 안에서"(양자화 덕분). 자막: "내려받는 순간 운영 책임도 함께 내려받아요."

### 만져 보기
- title: 모델 카드 읽기와 라우터 체험
- 위쪽(라이선스 판정기): select "모델 카드"(gpt-oss-20b / Qwen3-30B-A3B / DeepSeek-R1 / Llama 3.1 8B / Gemma 4 26B A4B — 사실 1~6의 라이선스·파라미터 값만). 체크박스 3개 "수업용 앱에 넣어 배포", "고쳐서 새 이름으로 공개", "이 모델 답으로 작은 모델 학습(증류)". 규칙 표(고정)에 따라 "가능 / 조건 있음(무슨 조건) / 카드에서 확인 필요" 표시. 예: Llama + 새 이름 공개 → "이름 앞에 Llama, Built with Llama 표시". DeepSeek-R1 + 증류 → "MIT에서 명시적으로 허용".
- 아래쪽(라우터): 전문가 칸 격자(선택 모델의 전문가 수: Qwen3 128, Gemma 4 128, Mixtral 예시 8; gpt-oss는 전문가 수 확인 불가이므로 라우터 영역 비활성 "카드에 전문가 수 미표기"). primary 버튼 "다음 토큰 보내기": `P.rng(토큰번호)`로 활성 전문가(8개 또는 2개) 점등, "활성 3.3B / 전체 30.5B" 표시, 토큰 문장 "쿼카가 교실에서 웃어요"를 한 토큰씩 진행.
- 첫 primary 클릭에서 점등 칸이 바뀌어야 함. desc 끝: "라우터 선택은 예시 값이에요. 라이선스·파라미터는 2026-10-02 공식 모델 카드 기준이에요."

### teacherLines
- 오픈 웨이트는 <b>모델 파일을 내려받을 수 있다</b>는 뜻이지, 아무 조건 없이 써도 된다는 뜻은 아니에요. 라이선스 칸부터 읽어요.
- 전문가 혼합 모델은 <b>전문가 몇 명만 골라 일을 시켜서</b> 크기에 비해 빨라요.

### tip
- body: 모델을 내려받기 전에 모델 카드에서 세 가지를 적어 두세요. ① license 칸(Apache-2.0·MIT·커스텀) ② 금지 용도 정책 링크가 있는지 ③ 전체 파라미터와 활성 파라미터. 커스텀이면 표시 의무·이름 규칙·이용자 수 조건을 따로 읽어요.
- extra: 학생 이름이 들어가는 실습이라면 오픈 웨이트 모델을 학교 기기에서 돌리면 글이 외부 서버로 나가지 않아요. 대신 유해 답변을 거르는 안전 장치와 업데이트는 학교가 직접 챙겨야 해요.

### myth
- myth: 오픈 웨이트 모델은 오픈 소스라서 학습 데이터까지 다 공개돼 있고, 누구나 마음대로 써도 된다.
- fact: 대부분 공개된 건 가중치예요. 오픈 소스 AI 정의는 데이터 정보·코드·가중치 셋을 다 요구해요. 쓰는 조건은 라이선스 칸이 정하고, 커스텀 라이선스에는 금지 용도와 표시 의무가 붙어요.

## 35 `v5-on-device` — 내 기기 안에서 도는 AI는 무엇이 다를까

- 부제: 소형 모델과 온디바이스 추론
- summary: 비행기 모드인데도 받아쓰기와 요약이 돼요. 휴대폰·노트북 안에서 돌아가는 소형 모델이 어떻게 작아졌는지(양자화·희소 활성화·플래시 저장), 그리고 글이 기기 밖으로 나가지 않는다는 개인정보 이점을 공식 문서로 짚어요.
- keywords: 온디바이스 AI, 엣지 컴퓨팅, 소형 언어 모델, 양자화, 희소 활성화, NPU, 오프라인, 개인정보, 프라이빗 클라우드 컴퓨트, Gemma, Gemini Nano

### 확인된 사실 목록
1. 안드로이드 개발자 공식 문서(Gemini Nano): 온디바이스 생성형 AI는 **프롬프트를 기기에서 실행해 서버 호출을 없애고**, 그래서 **민감한 데이터를 기기 안에 두어** 개인정보를 지키며, 오프라인으로 동작하고, 추론 비용을 줄여요. 네트워크 지연은 없지만 추론 속도는 기기 하드웨어에 달려 있어요. — https://developer.android.com/ai/gemini-nano (페이지 갱신 2026-09-08)
2. 안드로이드 개발자 블로그(2026-04-02): Gemma 4가 AICore 개발자 프리뷰로 제공되고, 올해 나올 Gemini Nano 4 탑재 기기에서 그대로 동작. 새 모델은 이전보다 **최대 4배 빠르고 배터리를 최대 60% 덜** 써요. E2B는 E4B보다 3배 빨라요. — https://android-developers.googleblog.com/2026/04/AI-Core-Developer-Preview.html (2026-04-02)
3. Gemma 4 공식 문서: 작은 E2B·E4B는 초소형 모바일·엣지·브라우저 배포용, Apache 2.0, 텍스트·오디오·이미지 입력. — https://ai.google.dev/gemma/docs/core (갱신 2026-07-08)

### 장면 5개 초안
1. 비행기 모드인데 돼요 — 쿼카(oops)가 비행기 모드 휴대폰 박스 앞. "받아쓰기: 됨 / 요약: 됨 / 최신 뉴스 질문: 안 됨" 3줄. 자막: "인터넷을 끊었는데 받아쓰기와 요약은 되고, 오늘 뉴스는 못 찾아요. 이 차이가 오늘 이야기예요."
2. 두 갈래 길 — 도식: 클라우드 경로(질문 → 인터넷 → 데이터센터 → 답, 화살표 길게) vs 온디바이스 경로(질문 → 기기 안 칩(NPU, AI 계산 전용 칩) → 답). 칩 3개: "서버 호출 없음", "글이 기기 밖으로 안 나가요", "오프라인 가능". 자막에 2026년 안드로이드 공식 문서 내용.
3. 작게 만드는 세 가지 방법 — 카드 3장. 양자화(숫자 하나를 16비트 대신 2비트로, 2025년 애플 3B 모델) / 희소 활성화(20B 중 1~4B만 깨움, 나머지는 플래시에 보관, 2026년) / 마트료시카 구조와 층별 임베딩 캐시(유효 2B, Gemma 3n). 자막: "작은 모델은 숫자를 줄이고, 필요할 때 일부만 깨워서 휴대폰에 들어가요."
4. 2026년 지금 — 타임라인 칩: "2026-04 Gemma 4 E2B·E4B, 배터리 최대 60% 절약" / "2026-06 애플 3세대: 3B + 20B(1~4B 활성)". 자막: "모바일 칩과 작은 모델이 같이 좋아져서, 기기 안에서 할 수 있는 일이 늘고 있어요."

## 36 `v5-grading` — AI 채점, 2026년 교실에서는 어디까지 믿을까

- 부제: LLM 심판의 편향과 수행평가 AI 관리 방안
- summary: 두 학생 답을 비교시켰더니 순서만 바꿔도 판정이 뒤집혔어요. AI를 심판으로 쓸 때 생기는 위치·장황함·자기 선호 편향을 잡는 방법과, 2026학년도부터 적용되는 교육부·교육청 수행평가 AI 관리 방안, 그리고 학생 평가를 고영향 AI로 둔 법까지 정리해요.
- keywords: AI 채점, LLM-as-a-judge, 위치 편향, 장황함 편향, 자기 선호 편향, 루브릭, G-Eval, 수행평가, AI 활용 관리 방안, 고영향 인공지능, 고위험 AI

### 확인된 사실 목록
1. 2023년 연구(Zheng 외, "Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena", NeurIPS 2023 Datasets and Benchmarks): LLM 심판의 한계로 **위치 편향, 장황함 편향, 자기 선호 편향, 제한된 추론 능력**을 밝히고 완화 방법을 제안. GPT-4 같은 강한 심판은 통제·크라우드 사람 선호와 **80% 넘게 일치 — 사람끼리 일치하는 수준**. 전문가 투표 3천 건, 사람 선호가 담긴 대화 3만 건 공개. — https://arxiv.org/abs/2306.05685 (arXiv v1 2023-06-09, 최종 2023-12-24)

2. 한국 시간표 — 가로 타임라인: 2025-01-21 공포 → 2026-01-20 시행령 의결 → **2026-01-22 시행** → 최소 1년 이상 계도(과태료 유예, 사실조사는 극히 예외) → 2026-07-21 일부개정 시행. 자막: "AI 기본법은 올해 1월 22일부터 시행 중이에요. 처음 1년 넘게는 계도 기간이라 조사는 큰 사고 같은 예외에만 해요."
3. 제31조 세 단계 — 카드 3장: ① 미리 알리기(사전 고지) ② 결과물에 표시 ③ 실제와 헷갈리는 딥페이크는 눈에 보이게(가시적 워터마크), 웹툰·애니메이션은 디지털 워터마크 + 알림 허용. 용어: 디지털 워터마크 = 눈에 안 보이게 파일에 심는 표시. 자막: "의무의 주인공은 AI 사업자예요. 그래도 같은 원칙을 수업 결과물에 적용하면 좋아요."
4. EU 시간표 — 타임라인: 2024-08-01 발효 → 2025-02-02 금지·AI 리터러시 → 2025-08-02 범용 AI → **2026-08-02 제50조 투명성** → 2027-12-02 고위험(교육 포함) → 2028-08-02 제품 내장 고위험. "연기" 표시는 디지털 옴니버스(2026-07-27 발효). 자막: "유럽도 올해 8월부터 AI 생성물 표시 의무가 시작됐어요. 시험 채점 같은 고위험 의무는 2027년 12월로 미뤄졌어요."
5. 두 법의 공통점 — 쿼카(point). 두 원 겹침 도식: 공통 "AI 생성물 표시", "AI와 대화 중임을 알리기", "학생 평가 = 특별 관리(한국 고영향, EU 고위험)". 자막: "두 법 다 '알리고, 표시하고, 평가는 조심'이에요. 교실 습관으로 먼저 시작해요."

## 39 `v5-energy` — AI는 전기와 물을 얼마나 쓸까

- 부제: 데이터센터 전력과 질문 한 번의 에너지
- summary: "AI한테 질문 하나 하면 물 한 병을 쓴대요." 정말일까요? IEA의 2026년 보고서와 2025년 실측 연구로 데이터센터 전체 전력, 질문 한 번의 전기·물, 그리고 영상·추론·에이전트가 왜 훨씬 많이 쓰는지 정리해요.
- keywords: 데이터센터, 전력 소비, TWh, IEA, Energy and AI, 질문당 에너지, Wh, 물 사용, 냉각, PUE, 제번스 역설, 추론 모델, 에이전트, 영상 생성

### 확인된 사실 목록
(1~7은 모두 IEA "Key Questions on Energy and AI"(World Energy Outlook 특별보고서, 2026-04 조판) — https://iea.blob.core.windows.net/assets/3179f7f8-01f6-4dd6-bffa-c9f7b73f1dc9/KeyQuestionsonEnergyandAI.pdf)
1. IEA는 2025년 4월 특별보고서 "Energy and AI"를 냈고, 2026년 보고서는 그 후속이에요. 2025년 보고서 기준 사례(Base Case): 데이터센터 전력이 **2024년 약 415 TWh → 2030년 약 950 TWh**로 두 배 이상. (2025년 보고서 발간 시점은 IEA 활동 문서로도 확인: https://iea.blob.core.windows.net/assets/7e263c7b-8dd2-4db3-bfe1-9a439f8a7e34/IEAActivitiesonEnergyandAI.pdf)
2. 2025년 데이터센터 전력은 **17% 늘어 약 485 TWh**("거의 500 TWh"), 세계 전력의 **약 1.5%**. 갱신 전망은 **2030년 약 950 TWh, 세계 전력 수요의 약 3%**. 부록 표 A.1: 2023년 360, 2024년 416, 2025년 485, 2030년 Base 945 TWh(2035년 값은 "탐색적 시나리오").
3. **AI 중심 데이터센터** 전력은 2025년에 **50%** 늘었고, 2030년까지 세 배 이상으로 **약 465 TWh**.
4. 질문 한 번: 구글은 Gemini 텍스트 프롬프트 중앙값 **0.24 Wh**, OpenAI는 ChatGPT 평균 질의 **0.34 Wh**, 마이크로소프트 연구는 2,000억 파라미터 넘는 최전선 모델 중앙값 **0.34 Wh**를 제시(모두 2025년 수치, IEA가 인용). 단순 텍스트 질의는 같은 시간 **텔레비전을 켜 두는 것보다 전기를 덜** 써요.
5. 작업 종류: 고해상도 이미지는 **약 10배**, 영상 생성은 길이·해상도에 따라 **수백~수천 배**, 추론 모델·에이전트 작업도 질의당 에너지가 훨씬 커요. IEA 그림 2.1(공개 모델 GPU 전력만, 지시용 수치): 중형 LM 0.05 Wh, 대형 MoE 0.31 Wh, 에이전트 1.14 Wh, 추론 7.6 Wh, 추론 켠 에이전트 50 Wh.
6. 효율과 사용량: 작업당 에너지는 최근 해마다 **최소 한 자릿수(10배)씩** 줄었지만, 효율이 좋아져 더 많이 쓰게 되는 **제번스 역설** 때문에 가까운 미래 총 전력은 늘어요. 최고 수준 데이터센터 PUE(전체 전력 ÷ IT 전력) **1.1~1.2**, 오래된 곳 **1.5~1.7**.
7. 지역 집중: 세계 전력의 1.5%지만, 데이터센터가 몰린 주·도시권에서는 **전력 수요의 20~30%**까지 차지.
8. 2025년 구글 실측 논문(Elsworth 외): Gemini 앱 텍스트 프롬프트 중앙값 **에너지 0.24 Wh, 물 0.26 mL(약 다섯 방울)**, "텔레비전 9초 시청보다 적은 에너지". 12개월 동안 프롬프트당 에너지 **33배**, 탄소 **44배** 감소. — https://arxiv.org/abs/2508.15734 (arXiv 2025-08-21)
9. 2023년 물 발자국 연구(Li 외, "Making AI Less Thirsty"): GPT-3를 미국의 최신 마이크로소프트 데이터센터에서 학습하면 **깨끗한 담수 약 70만 L를 직접 증발**시킬 수 있고, 세계 AI 수요는 **2027년 물 취수량 42억~66억 m³**로 전망(덴마크 4~6개 나라, 영국의 절반 수준 연간 취수량보다 많음). — https://arxiv.org/abs/2304.03271 (arXiv v1 2023-04-06, v5 2025-03-26)
- 확인 실패: **IEA 공식 웹페이지 https://www.iea.org/reports/energy-and-ai 는 WebFetch에서 403(접근 차단)**이라 직접 열지 못했어요. 대신 같은 기관이 iea.blob.core.windows.net에 올린 공식 PDF(2026 후속 보고서)에서 2025년 보고서 수치를 확인했어요. 2025년 보고서 원문 PDF(https://iea.blob.core.windows.net/assets/dd7c2387-2f60-4b60-8c5f-6563b6aa1e4c/EnergyandAI.pdf)는 내려받았지만 본문 파싱에 실패 → "2030년 945 TWh"는 2026 보고서 부록 표 값으로만 인용.
- 확인 불가: 데이터센터 전체 물 사용량(IEA 2026 요약에 없음), "질문 하나에 물 한 병" 같은 통설의 출처, 휴대폰 충전 1회 Wh(그림 기준선만 있고 수치 없음).

### 장면 5개 초안
1. 질문 하나에 물 한 병? — 쿼카(oops). 말풍선 "AI한테 질문 하나 하면 물 한 병 쓴대!" + 물병 아이콘(P.h 사각형). 자막: "학생이 이렇게 물었어요. 공식 측정값으로 확인해 볼게요."
2. 질문 한 번의 크기 — 숫자 카드 3장: "0.24 Wh", "0.26 mL(약 다섯 방울)", "TV 9초보다 적어요". 자막: "2025년 실측으로 텍스트 질문 한 번은 전기 0.24와트시, 물 0.26밀리리터였어요. 물 한 병과는 거리가 멀어요."
3. 그런데 종류가 달라지면 — 로그 막대(그림 2.1 값): 중형 0.05 / 대형 MoE 0.31 / 에이전트 1.14 / 추론 7.6 / 추론+에이전트 50(Wh). 별도 칩: "이미지 약 10배", "영상 수백~수천 배". 자막: "그림은 열 배쯤, 영상은 수백에서 수천 배예요. 오래 생각하는 추론과 여러 단계를 도는 에이전트도 훨씬 많이 써요."
4. 다 합치면 — 데이터센터 전력 막대: 2024 415 → 2025 485(세계 1.5%) → 2030 약 950 TWh(약 3%). 칩: "AI 전용 센터 2025년 +50%", "몰린 지역은 전력의 20~30%", "효율 10배 좋아져도 더 많이 써요(제번스 역설)". 자막: "한 번은 작아도 횟수가 엄청나서, 데이터센터 전력은 2030년까지 두 배가 돼요."
5. 교실 판단 — 쿼카(point). 체크 카드 3장: "글로 되는 일은 글로", "영상은 스토리보드 확정 후 한 번에", "같은 영상 무한 재생성 줄이기(시드·프롬프트 기록)". 자막: "AI 전기는 한 번의 양 곱하기 횟수예요. 영상처럼 큰 작업은 계획하고 한 번에 만들어요."

### 만져 보기
- title: 우리 반 AI 전기 계산기
- range 4개: 학생 수(1~30), 1인당 텍스트 질문(0~50), 1인당 이미지(0~20), 반 전체 영상(0~10).
- 계산(고정 계수): 텍스트 0.24 Wh(사실 8), 이미지 = 텍스트 × 10(사실 5 "약 10배"), 영상 = 텍스트 × 300(사실 5 "수백~수천 배" 중 **낮은 쪽 가정**이라고 화면에 명시). 합계 Wh, 그리고 "TV 시청 환산" = 합계 ÷ 0.24 × 9초 이하(사실 8 비교를 그대로 늘린 상한 환산).
- 막대: 텍스트·이미지·영상 기여 비율. primary 버튼 "영상 1편 추가": 영상 +1 → 영상 막대가 크게 늘어 DOM 변경.
- desc 끝: "텍스트 1회 값은 2025년 실측 중앙값, 이미지·영상 배수는 IEA 범위에서 고른 예시 값이에요."

- body: 영상 생성 수업은 스토리보드·프롬프트를 글로 먼저 확정하고, 장면당 생성 횟수를 정해 두세요(예: 장면당 2회). 마음에 든 결과의 시드와 프롬프트를 기록하면 같은 걸 다시 뽑느라 쓰는 전기가 줄어요.

## 40 `v5-choose` — 우리 학교 AI 도구, 2026년엔 무엇을 보고 고를까

- 부제: 모델 카드, 데이터 처리, 위험 관리 체크리스트(2026판)
- summary: 2학기 연구회에서 AI 도구 후보 세 개를 놓고 골라야 해요. 광고 대신 모델 카드·데이터 처리 위치·위험 관리 틀·2026년 법과 지침으로 만든 체크리스트로 판단해요. 시즌 5와 40편 전체를 마무리하는 편이에요.
- keywords: AI 도구 선택, 모델 카드, 라이선스, 데이터 처리 위치, 입력 학습 활용, 개인정보 처리 안내서, NIST AI RMF, 생성형 AI 프로파일, 사전 고지, 고영향 AI, 체크리스트

### 확인된 사실 목록
1. 모델 카드(Mitchell 외, FAT* 2019): 머신러닝 모델에 붙이는 문서로, **문화·인구·외형 집단별(교차 집단 포함) 성능 평가**, **의도된 사용 맥락(써도 되는 곳과 안 되는 곳)**, 성능 평가 절차를 담아요. — https://arxiv.org/abs/1810.03993 (arXiv v1 2018-10-05, v2 2019-01-14; 학회 2019-01-29~31)
2. NIST AI RMF 1.0: **2023-01-26 공개, 자율(voluntary) 사용** 틀. 네 기능 Govern(다스리기)·Map(파악)·Measure(측정)·Manage(관리). **2024-07-26 생성형 AI 프로파일(NIST AI 600-1)** 공개. AI RMF 1.0은 **백악관 AI 실행계획에 따라 개정 중**이고, 2026-04-07 핵심 기반시설용 프로파일 개념 노트 공개. — https://www.nist.gov/itl/ai-risk-management-framework
3. 개인정보보호위원회 「생성형 인공지능(AI) 개발·활용을 위한 개인정보 처리 안내서」(**2025-08-06** 공개): 생성형 AI 생애주기를 **① 목적 설정 ② 전략 수립 ③ 학습 및 개발 ④ 적용 및 관리** 4단계로 나눠 단계별 최소 안전조치 제시. 전략 수립 단계는 개발 방식을 나눠 유형별 위험 경감 방안 안내, 학습·개발 단계는 데이터 오염·탈옥 위험과 **AI 에이전트 관리 방안**, 적용·관리 단계는 정보주체 권리 보장. 전 과정에 **개인정보 보호책임자(CPO) 중심 거버넌스**. — https://www.korea.kr/news/policyNewsView.do?newsId=148947194 (2025-08-06), 원문 게시 https://www.privacy.go.kr/front/bbs/bbsView.do?bbsNo=BBSMSTR_000000000049&bbscttNo=20836
4. 인공지능기본법 제31조: 고영향·생성형 AI 제품·서비스는 **AI 기반 운용 사실을 사전 고지**, 생성형 AI 결과물 **표시**. 제2조 제4호: **학생 평가**는 고영향 AI 영역. — https://www.law.go.kr/LSW//lsSideInfoP.do?lsiSeq=282791&joNo=0031&joBrNo=00&docCls=jo&urlMode=lsScJoRltInfoR , https://www.law.go.kr/LSW//lsSideInfoP.do?lsiSeq=282791&joNo=0002&joBrNo=00&docCls=jo&urlMode=lsScJoRltInfoR
5. 처리 위치: 온디바이스 처리는 서버 호출 없이 민감한 데이터를 기기에 둬요(안드로이드 공식, 2026-09-08 갱신 https://developer.android.com/ai/gemini-nano). 애플 서버 모델은 Private Cloud Compute에서 "사용자 데이터를 애플 포함 누구에게도 저장·공유하지 않는다"(2026-06-08 https://machinelearning.apple.com/research/introducing-third-generation-of-apple-foundation-models).
6. 라이선스: 오픈 웨이트 모델 카드의 license 칸은 Apache-2.0·MIT·커스텀(금지 용도 정책·표시 의무 동반)으로 나뉘어요(34편 사실 1~5).
7. 수행평가 AI 관리 방안(2025-12-23): 평가 전에 AI 활용 기준 마련, 활용 과정 표기, 개인정보 주의(36편 사실 3~4).
- 확인 불가: 개인정보위 안내서의 "서비스형 LLM 이용자 확인 사항"(입력 학습 활용 여부·약관 등) 구체 문장 — 정책브리핑 본문에서 해당 문장을 찾지 못했어요. 체크리스트의 "입력을 학습에 쓰지 않는 설정" 항목은 시즌 4 편과 같은 연구회 기준으로 두고, 안내서 인용으로 쓰지 말 것. 개발 방식 유형 이름도 확인 불가.

### 장면 5개 초안
1. 후보 세 개 — 쿼카(think). 도구 A·B·C 카드(가상 이름), 각자 광고 문구. 자막: "2학기 연구회 과제예요. 후보 세 개 중 하나를 골라야 해요. 이번엔 문서 네 장으로 골라요."
2. 문서 1: 모델 카드 — 카드 모형에 칸 4개: 학습 데이터 / 써도 되는 곳·안 되는 곳 / 집단별 성능 / 라이선스(오픈 웨이트면). 자막: "2019년에 제안된 모델 카드는 모델이 어디에 맞고 어디에 안 맞는지 적는 문서예요. 집단별 성능까지 적게 해요."
3. 문서 2: 내 글은 어디로 — 경로 도식 세 갈래: 기기 안 / 서버(저장 안 함 명시) / 서버(학습 활용 여부 확인 필요). 칩: "2025년 개인정보위 안내서: 목적 → 전략 → 학습·개발 → 적용·관리, CPO 중심". 자막: "학생 글이 기기 안에서 끝나는지, 서버로 가는지, 가서 남는지를 먼저 확인해요."
4. 문서 3·4: 위험 관리와 법 — 왼쪽 NIST 네 기능 순환(다스리기·파악·측정·관리, 2024 생성형 AI 프로파일 칩), 오른쪽 한국법 칩 2개("AI 기반임을 미리 알리나?", "평가에 쓰면 고영향"). 자막: "위험 관리 틀은 누가 책임지고, 어디에 쓰고, 어떻게 재고, 문제 생기면 어떻게 할지 묻게 해요. 평가에 쓸 도구라면 사람 검토가 꼭 들어가야 해요."
5. 체크리스트와 마무리 — 쿼카(wave). 체크 10줄 요약 → 점수 → "도입 / 조건부 / 보류" → "한 학기 뒤 다시". 시즌 5 회고 칩 7개(모델 붕괴·오픈 웨이트·온디바이스·AI 채점·리터러시·법·에너지)가 체크리스트로 모이는 화살표. 자막 마지막: "원리를 알면 고를 수 있고, 고를 수 있으면 가르칠 수 있어요. 40편 함께해 줘서 고마워요."

### 만져 보기
- title: 2026 도구 고르기 점수판
- 항목 10개(체크박스, 가중치): 모델 카드·한계 문서 공개(1) / 라이선스 확인(오픈 웨이트일 때, 1) / 처리 위치 명시(2) / 입력을 학습에 쓰지 않는 설정(2, 연구회 기준) / 보관 기간 명시(2) / 연령·학생 사용 조건(2) / AI 기반임을 사전 고지(1) / AI 생성물 표시 기능(1) / 문제 신고 창구(1) / 에너지 큰 기능(영상) 사용 조절 가능(1).
- select "처리 위치": 기기 안 / 서버(저장 안 함 명시) / 서버(정보 없음) — "서버(정보 없음)"이면 등급 상한 "조건부".
- 토글 "평가(채점)에 쓸 예정": 켜면 "사람 최종 검토 절차" 필수 항목이 추가되고, 미체크 시 등급 "보류"(고영향 영역 안내 문구).
- primary 버튼 "도구 A로 채우기"(가상 예시 상태) → 점수·등급·부족 항목 갱신. 보조 버튼 "도구 B", "초기화".
- 시즌 4 `s4-choose`(체크 8개 단순 합산)와 달리 **처리 위치 select + 평가 용도 토글**로 등급 규칙이 바뀌는 게 핵심.
- desc 끝: "가중치와 등급 기준은 연구회 예시예요. 도구 A·B는 가상의 예시예요."

### teacherLines
- 좋은 AI 도구는 <b>못 하는 것</b>과 <b>내 글이 가는 곳</b>을 문서로 밝혀요.
- AI 도구는 한 번 고르고 끝이 아니라 <b>한 학기 써 보고 다시 점검</b>해요.

### tip
- body: 후보마다 문서 네 장(모델 카드·개인정보 처리방침·이용약관의 연령 조건·AI 사용 고지 화면)을 캡처해 한 폴더에 모으고, 점수판으로 채점하세요. 평가에 쓸 도구는 "사람 최종 검토" 절차를 먼저 정한 뒤에만 도입해요.
- extra: 가중치는 학교 상황에 맞게 바꿔도 돼요. 다만 처리 위치·보관 기간·연령 조건(개인정보 세 항목)은 낮추지 마세요.

### myth
- myth: 유명하고 많이 쓰는 도구면 학교에서 써도 안전하다.
- fact: 유명함과 데이터 처리 위치·보관·연령 조건은 별개예요. 문서로 확인하고, 평가에 쓰면 법이 정한 고영향 영역이라 사람 검토가 필요해요.
